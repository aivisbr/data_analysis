Diktāts Pipeline Map

The app runs the same Latvian dictation reading through several speech-to-text models and scores each transcript against the ground truth. Audio reaches it in one of two ways: a live recording from a browser tab, or an uploaded audio file. Everything it produces is saved on this laptop under one storage root. Audio goes to a provider only when that run's paid flag is switched on.

The storage root is the project folder, C:\Users\a.brutans\codex_proj\p7_diktats, unless P7_STORAGE_ROOT is set. Reading A is saved in Try1/ and reading D in Try2/, and the two are saved and scored separately.

How scribe_v3 gets through

The new ElevenLabs IDs don't have their own capability profiles. They are registry entries that reuse the Scribe v2 profile, and the code only lets through IDs from a short fixed list. The ID you choose is sent unchanged. Live sessions also check that ElevenLabs reports the same ID back.

Where things live

Storage map

All paths are relative to the storage root. Raw transcripts are never edited. The editable copies are the ones you correct, and every evaluation re-reads files from disk instead of using cached text.

data/ — app state and prepared audio

data/app.sqlite3

The model registry: the Live and Audio-file lists, each model's settings, and a frozen snapshot of the models used in each run. Deleting a model never deletes past runs.

data/audio/uploads/<id>/

original.wav|mp3 exactly as uploaded, plus preview.wav and metadata.json.

data/audio/prepared/<id>/

The chosen interval as interval.wav and chunk_0000.wav… at 24 kHz mono, with a SHA-256 for each chunk in metadata.json.

data/evaluation_inputs/<id>/

Server-side copies of transcript files you uploaded for scoring.

data/rehearsals/T026_<id>/

Isolated rehearsal packages made by scripts/rehearse_workflow.py. These never touch real runs.

runs/ — one folder per run, live or file

runs/<run>/metadata.json

The run record: models with requested and effective settings, attempts, statuses and errors. Provisional text is kept here as a checkpoint.

runs/<run>/file_job.json

fileChunk order, hashes, and the provider, model ID and SDK version used.

runs/<run>/Try1/ · Try2/

Reading A goes in Try1 and reading D in Try2. A live recording of A and one of D are separate runs.

audio.wav · source_frames.jsonl

liveThe original recording and its frame log. While paused it is audio.partial.wav.

distribution.json

liveEach model's config for each segment: SDK version, commit policy, padding, and safe error codes.

raw/*.txt

The exact model output for each model attempt. Never overwritten.

editable/*.txt

A copy you can correct before scoring.

evaluations/ — one folder per scoring

evaluations/<id>/

ground_truth.txt, inputs/000.txt… and metadata.json are a frozen snapshot of the inputs. legacy_scores.json holds WER/CER, diagnostics.json holds punctuation, case and NFC checks, and results.json/.csv are the exports. A changed source file needs a new evaluation; old ones are never overwritten.

Read-only references

example/

The ground truth LSMzinas_lav_GT.txt and older transcripts from other tools in example/tests/. Never edited.

docs/api_test_usage.json

The ledger of paid test runs and spending.

Testing

Four kinds of test, four places

Offline unit tests

tests/test_*.py

These run the real SDKs against fake WebSocket and HTTP transports. No keys, network or cost, and nothing is written outside temporary folders.

.venv\Scripts\python.exe -m unittest discover -s tests -v

Always run them through discover, because some test modules import each other by bare name.

DEMO runs

runs/<run>/ (marked [DEMO])

Free runs with synthetic text through the full app flow. They are saved like real runs, and the history labels them DEMO so they are never mistaken for paid results.

Workflow rehearsal

data/rehearsals/T026_<id>/

Synthetic PCM and injected text, used to practise import, editing and scoring in the browser. Each run produces a report.json and a ui/ folder of files to import.

.venv\Scripts\python.exe scripts/rehearse_workflow.py

Paid provider tests

runs/<run>/ + docs/api_test_usage.json

You run these yourself from start_paid.cmd. The plan is in docs/T024_PAID_TEST_MATRIX.md and the findings in docs/T025_SMOKE_RESULTS.md. ElevenLabs is outside the $10 OpenAI/Gemini budget, so log it separately.
